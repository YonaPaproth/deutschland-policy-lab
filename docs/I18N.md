# Internationalisation (i18n) — Adding German Localisation

This document describes how to add full German-language support to Deutschland Policy Lab. This corresponds to **Module G** in the roadmap.

---

## Recommended Library

Use [`next-intl`](https://next-intl-docs.vercel.app/) (maintained, well-integrated with the Next.js App Router, supports server components).

```bash
npm install next-intl
```

Alternative: `next-i18next` (older, pages-router-first) — not recommended for this project since it uses the App Router.

---

## File Structure

After adding i18n, the project structure should look like this:

```
messages/
  en.json          ← English strings (source language)
  de.json          ← German strings (target language)

app/
  [locale]/
    layout.tsx     ← Root layout with locale provider
    page.tsx       ← Homepage (locale-aware)
    ...

middleware.ts      ← next-intl locale detection and redirect
```

All user-facing strings currently hardcoded in components move into the message files.

## Key Terms to Translate

Policy terminology requires expert translation — do not rely on machine translation for the following:

| English | Recommended German | Notes |
|---------|-------------------|-------|
| Evidence strength | Evidenzstärke | Standard in German-language EBP literature |
| Implementation difficulty | Umsetzungsschwierigkeit | Or: Implementierungsschwierigkeit |
| Expected impact | Erwartete Wirkung | Not "Impact" — use German |
| Confidence | Konfidenz / Gewissheitsgrad | Konfidenz is used in statistics; Gewissheitsgrad in policy contexts |
| Policy | Politik (domain) / Maßnahme (specific measure) / Regelung (regulation) | Context-dependent — do not use "Policy" as a loanword |
| Intervention | Intervention / Maßnahme | Intervention is acceptable in academic German |
| Counterarguments | Gegenargumente | |
| Falsifiability | Falsifizierbarkeit | Standard philosophical term |
| State capacity | Staatliche Handlungsfähigkeit | Leistungsfähigkeit is also common |
| Coalition feasibility | Koalitionsfähigkeit | |
| Pilot | Pilotprojekt / Erprobung | |

## German Policy Terminology Considerations

**Federalism:** Germany's federal structure means some policies are *Bundesangelegenheiten* (federal matters) and others are *Ländersache* (state matters). The German UI should use these terms where relevant, not English equivalents.

**Legal precision:** German policy language is more legalistic than English. Where an English entry says "regulations," German may need to distinguish between *Gesetze* (laws), *Verordnungen* (statutory instruments), *Verwaltungsvorschriften* (administrative guidelines), and *Satzungen* (by-laws).

**Institutional names:** Do not translate proper names of German institutions. *Sachverständigenrat*, *Bundesnetzagentur*, *Bundesverfassungsgericht*, etc. should remain in German in both the English and German versions.

**Numbers and units:** German uses a period as the thousands separator and a comma as the decimal separator (1.000.000,50 €). Ensure number formatting is locale-aware via `Intl.NumberFormat`.

## Implementation Steps

1. Install `next-intl` and configure `middleware.ts` for locale detection.
2. Create `messages/en.json` by extracting all hardcoded strings from components.
3. Wrap the app in `NextIntlClientProvider` and update all components to use `useTranslations()`.
4. Create `messages/de.json` — work with a native German-speaking policy expert, not a machine translator alone.
5. Add a locale switcher to the navigation (flag or "DE | EN" toggle).
6. Translate policy content fields (`title`, `problem`, `objective`, `intervention`, etc.) — this is the bulk of the work. Consider a parallel `data/policies.de.ts` file or a `translations` sub-object on each policy.
7. Ensure the AI prompt (in `lib/ai/`) generates responses in the user's locale.
8. Update CI to lint and type-check both locales.
